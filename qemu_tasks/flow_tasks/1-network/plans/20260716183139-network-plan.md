## Conclusions

The current `index.html` already contains a working **delegate** path:
`Module['websocket'] = { url: netParam.param }`, then appends
`n:<mac>` to the boot `info` blob and calls `start(info)`. The task is a
UX/scope reduction: strip the browser path and drive the delegate path from a
modal instead of `location.search`.

Implementation is confined to `qemu/index.html`. No generated artifacts change.

### Detailed approach (single file: `qemu/index.html`)

1. **Head/CSS**: add an inline `<style>` block implementing a cyberpunk theme
   (dark background, neon cyan/magenta accents, monospace, glow/scanline
   accents). Style: `body`, `#terminal` container, and a modal overlay
   (`#net-modal`, input, buttons). Keep `vendor/xterm.css` link.

2. **Markup**: keep `<div id="terminal">`. Add a modal overlay markup with:
   - a title/blurb,
   - a text `<input id="net-url" placeholder="ws://localhost:8888">`,
   - a "Connect" button and a "No network" button (or a single Start button;
     empty field == no network). Plan: one input + "Start" button, plus helper
     text explaining empty == disabled. Also support Enter to submit.

3. **Script (module)**: restructure so terminal/pty/module setup and the
   `start(info)` / `getNetParam`(removed) / `genmac()` helpers remain, but the
   boot is triggered from a `bootWithNet(url)` function invoked by the modal:
   - Move xterm/openpty/`Module.pty`/`mainScriptUrlOrBlob` creation to run
     *after* the user submits (Phase 2), OR keep terminal creation early but
     only call `initEmscriptenModule` after submit. Decision: create the
     xterm + pty in Phase 2 (after submit) so "2 phases" is literal and the
     terminal appears with the VM. The modal is Phase 1.
   - `bootWithNet(url)`:
       - `let info = "t:" + epoch + "\n";`
       - if `url` non-empty/trimmed: `Module['websocket'] = { url };`
         `info += 'n:' + genmac() + '\n';`
       - call existing `start(info)` (unchanged pty/preRun/poll logic).
   - Remove `getNetParam`, browser-mode branch, `Stack`, proxy env block.

4. **Remove** the `<script src="./dist/stack.js"></script>` tag (only used by
   browser mode).

### Key facts / wiring to preserve

- Delegate proxy value flows into `Module['websocket'].url`. The example
  `ws://localhost:8888` matches `arg-module.js` `-netdev socket,...connect=127.0.0.1:8888`
  — c2w's websocket transport bridges the guest NIC socket to the proxy WS.
- `info` blob lines: `t:<epoch>`, and when networked `n:<mac>`. These are
  written to `/pack/info` in preRun and consumed by the guest init. Do not
  change their format.
- `genmac()` stays. `start(info)` stays byte-for-byte.

## Constraints/Dependencies

- Language: plain HTML/CSS/JS module, no framework.
- Only edit `qemu/index.html`. Do not touch `load.js`, `out.js`, `*.wasm`,
