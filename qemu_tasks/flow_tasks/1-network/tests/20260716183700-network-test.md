## Manual verification (NOT automatable here): full `ping 1.1.1.1`

Automated headless execution is **blocked**: the ping path needs a real browser
with SharedArrayBuffer (cross-origin-isolated) plus a *live* `c2w-net` delegate
proxy on the entered `ws://` URL. No headless browser or c2w-net proxy is
installed on this host, and the guest VM boot cannot be driven from Node. This
is recorded as documented manual verification.

Preconditions: all boot artifacts are present in `qemu/` (`load.js`, `out.js`,
`qemu-system-x86_64.wasm` 40M, `qemu-system-x86_64.data` 390M), so only a proxy
+ browser are missing.

Manual steps:

1. Start a delegate proxy (container2wasm's `c2w-net`) listening on a WS port,
   e.g. `c2w-net --listen-ws localhost:8888` (exact flags per your c2w-net
   build; it must speak the c2w socket-over-WS protocol on `ws://localhost:8888`).
2. Serve the page:  `cd qemu && node server.mjs`  (defaults to port 8080;
   `PORT=8080`). Cross-origin isolation headers are already set.
3. Open `http://localhost:8080/` in Chrome/Firefox. Confirm the cyberpunk
   "// Net Uplink" modal appears before any terminal.
4. Type `ws://localhost:8888` into the field and click "Connect & boot"
   (or press Enter). The modal hides; the xterm terminal renders and the VM
   boots.
5. At the guest shell prompt run:  `ping 1.1.1.1`
   Expected: ICMP replies stream (`64 bytes from 1.1.1.1: icmp_seq=... ttl=...
   time=... ms`), proving the guest NIC bridged through the delegate proxy to
   the internet.

Air-gapped control (Grill1 F1 / Grill2 G2-2), also manual:

6. Reload, leave the field empty, click "No network" (or Enter on empty input).
   Expected: VM boots to a shell prompt WITHOUT hanging; `ping 1.1.1.1` fails
   cleanly (network unreachable / no such device) rather than stalling on a dead
   `ws://127.0.0.1:8888`. `disableGuestNetwork()` having removed the NIC is the
   code-level guarantee behind this; step 6 is the behavioral confirmation.

Next command to attempt automation (for a future agent with a browser):
